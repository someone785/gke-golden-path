# ADR 0002: GKE はゾーン型のクラスタにする

- 状態: 決定
- 日付: 2026-11-08

## 背景
GKE のクラスタは、コントロールプレーン (API サーバーなど、クラスタの司令塔) の置き方で 2 種類に分かれる。

- **ゾーン型**: コントロールプレーンを 1 つのゾーンに置く。
- **リージョン型**: コントロールプレーンを、リージョン内の複数のゾーンに複製する。

## 選択肢と比較

| | ゾーン型 | リージョン型 |
|---|---|---|
| コントロールプレーン | 1 つのゾーン | 複数のゾーンに複製 |
| ノードの配置 (既定) | 1 つのゾーン (複数のゾーンにもできる) | 3 つのゾーンに分散 |
| コントロールプレーンのアップグレード中・障害時 | API が一時的に使えない (`kubectl` や ArgoCD の同期が止まる)。動いている Pod は動き続ける | API を使い続けられる |
| コスト | 安い | ノードが増えやすく、ゾーンをまたぐ通信も増える |

## 決定
ゾーン型にする。

## 理由
- 使うのは作者 1 人だけ。コントロールプレーンが一時的に止まっても、Pod は動き続けるので、デモの画面は落ちない。
- コストを抑えて、無料クレジット (期限は 2027 年 1 月 27 日) を長く使いたい。
- 管理手数料には、請求先アカウントごとに、ゾーン型のクラスタ 1 つ分の無料枠があったと記憶している。
  ただし、**未確認**なので、公式の料金ページで確認する。
- **本番の環境なら、可用性を優先してリージョン型を選ぶ。** 今回は、そのトレードオフを理解したうえで、コストを優先した。

## 結果
- 【作成後に、ゾーン型とリージョン型は切り替えられない】
  Terraform の `location` を変えると、クラスタは作り直し (`replace`) になる。
- 【リージョン型にする場合、ノード数はゾーンごとの指定になる】
  たとえば `node_count = 2` は、2 台 × 3 ゾーン = 6 台になる。将来リージョン型に移るときは、ここに注意する。
- Spot が確保できない場合は、コントロールプレーンはゾーン型のまま、ノードプールだけを複数のゾーンに置く (`node_locations`)。
  ゾーンをまたぐ通信の料金が増えるが、その金額は**未確認**。
